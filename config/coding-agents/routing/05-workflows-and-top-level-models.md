Every top-level tab, lane and workflow orchestrator runs `opus-latest` at medium with ultracode off by default, never xhigh, max or Fable. A lead turns on high or ultracode for one task of architecture, scoping, review verdicts or visual judgment and records why; an explicit setting from Alex stands. Wake-only tabs keep their current allocation. Every Workflow `agent()` call names its route: helpers pass `model: 'gpt-6.1-sol'` or a typed GPT `agentType`, and only judge, synthesis or visual stages pass `model: 'opus'` at `effort: 'medium'`. A child that names no model runs the launcher's helper model: `claude-launch` sets `CLAUDE_CODE_SUBAGENT_MODEL` and `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` to the launch helper (`sol-latest` unless `launch.json` names `helper_model`), keeps an explicit `claude-*` value from the caller's environment, and leaves `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=0` so a named model wins. Exporting `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL=claude-opus-5-5` before launch rolls it back for that session. The claude-config `child-routing` hook only warns and logs each unrouted call to `~/.agent-rails/factory/child-routing.jsonl`, because Claude Code ignores hook-rewritten Workflow and Agent input; `{"mode": "off"}` in `child-routing.json` silences it. Proof of a route is the served model in the child transcript and on the agent-lb row, never the label. Review runs on request only (see Merging, deploy and review); escalate failed work through the existing quality checks. Workflows fan out without an agent cap; host admission throttles only at real memory or disk floors.
